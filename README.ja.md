# TrackMatch

[English](README.md)

TrackMatchは、音楽ライブラリから音響的に重複している、または非常によく似た音源を見つけ、どのファイルを残すか整理するためのWindowsデスクトップアプリケーションです。

Chromaprintのフィンガープリントを利用して音声を比較するため、ファイル名やタグ、音量、マスタリング、曲の前後の無音部分などが異なっていても比較できます。現在正式に対応している音声形式はFLACとMP3です。

## 重要な注意事項

TrackMatchには、整理対象となった音声ファイルを指定したごみ箱フォルダーへ実際に移動する機能があります。ファイル整理を実行する前に、重複判定の内容と移動先を十分に確認してください。

**重要なファイルは、TrackMatchを利用する前に必ずバックアップしてください。**

## 動作環境

### リリース版を利用する場合

- Windows 10 または Windows 11

Windows向けリリースZIPには、必要なChromaprint `fpcalc`とネイティブ音声ライブラリが同梱されています。通常の利用では.NET SDKを別途インストールする必要はありません。

### 開発する場合

- .NET 10 SDK

## 基本的な使い方

1. GitHub ReleasesからWindows x64向けZIPを取得し、任意のフォルダーへ展開します。
2. `TrackMatch.App.exe`を起動します。
3. ライブラリを作成し、FLACまたはMP3ファイルが入っているフォルダーを1つ以上登録します。
4. 解析を実行します。TrackMatchがライブラリを走査し、フィンガープリントの取得、比較候補の生成、類似度の判定を行います。
5. 候補を確認して、次のいずれかでレビューします。
   - `重複ではない` — 2つのファイルを重複ではないと判定します。
   - `重複 / Aを残す` — 重複と判定し、Aを優先するファイルとして記録します。
   - `重複 / Bを残す` — 重複と判定し、Bを優先するファイルとして記録します。
6. 重複グループと、最終的に残すファイルを確認します。
7. 必要に応じてごみ箱フォルダーを設定し、削除候補となったファイルの移動を明示的に実行します。

候補をレビューしただけでファイルが自動的に移動されることはありません。実ファイルの整理は独立した明示的な操作です。

## 重複判定と残すファイルの決まり方

物理的な音声ファイルは、ライブラリへの所属とは独立したTrackとして管理されます。そのため、同じファイルが複数のライブラリに所属することがあります。

比較候補は、少なくとも1つの同じライブラリ内に存在するTrack同士について生成されます。同じ物理ファイルの組み合わせに対するレビュー判定は、ライブラリをまたいで共有されます。

重複と判定するときは、同時にどちらのファイルを優先するかを記録します。この優劣関係から重複グループが構成され、TrackMatchは蓄積されたレビュー判定をもとに、各ライブラリで残すファイルを自動的に導出します。ライブラリごとに独立した「残すファイル」を手動保存する方式ではありません。

3ファイル以上の重複グループでは、残すファイルを確定するために必要な場合だけ追加の比較を求めることがあります。残すファイルの決定に影響しない組み合わせは、レビューを省略する場合があります。

レビュー判定同士に矛盾がある場合や、ファイル内容の変更によって再評価中の場合は、安全な状態になるまで影響範囲のファイル整理を停止します。

## 解析と再スキャン

ライブラリのスキャンでは、登録フォルダー以下にある対応済みのFLACとMP3を再帰的に読み取ります。TrackMatchはメタデータ、フィンガープリント、比較結果、レビュー状態などをローカルデータベースへ保存します。

2回目以降のスキャンでは、変更されていないファイルの解析結果を再利用します。正常に走査できたライブラリルートからファイルがなくなった場合、そのTrackを直ちに削除するのではなく「見つからない」状態として管理します。

既知のファイルが変更された場合は、可能な範囲でメタデータだけの変更と音声内容そのものの変更を区別します。メタデータが変わっただけで既存のレビュー判定を破棄することはありません。音声内容が変更されたと確認された場合は、影響する解析結果と直接関連するレビュー状態を再評価します。

## Track管理

Track管理画面では、すべてのTrack、見つからなくなったTrack、どのライブラリにも所属していないTrackなどを確認できます。また、強制再解析やTrackMatchが管理しているデータの明示的な削除も行えます。

強制再解析では、再計算が必要な解析データを無効化します。Trackの削除操作で削除されるのはTrackMatchが管理するデータであり、元の音声ファイルそのものは削除しません。

## ライブラリルートの移動

音楽フォルダーを移動した場合は、ライブラリルートを新しい場所へ再割り当てできます。可能な限りTrack IDと再利用可能な解析結果を維持したまま所属パスを更新し、移動先に存在しないファイルは「見つからない」状態にします。

パスの衝突は変更を適用する前に検査します。移動先が別ライブラリのルートと重なったという理由だけで、無関係なライブラリへの所属を自動追加することはありません。

## ごみ箱とファイルの安全性

ごみ箱への移動は明示的な操作です。削除候補となったファイルは設定したごみ箱フォルダー以下へ移動し、移動先に既存ファイルがある場合は上書きしません。

1つの物理ファイルが複数のライブラリから共有されている場合、そのファイルを移動すると参照しているすべてのライブラリに影響します。TrackMatchはこの関係を確認し、現在の重複判定やレビュー状態を安全に適用できない場合はファイル整理を停止します。

物理ファイルの移動後にデータベース更新が失敗した場合は、エラーを報告する前に元の場所へファイルを戻す処理を試みます。ただし、これは安全性を高めるための仕組みであり、バックアップの代わりになるものではありません。

ごみ箱から元の場所へ手動でファイルを戻した場合は、後続のスキャンで再検出できます。可能な場合は既存のTrackを再利用し、過去の削除判断をそのまま適用するのではなく、現在のファイル整理状態を再計算します。

## ビルド

```powershell
dotnet restore TrackMatch.slnx
dotnet build TrackMatch.slnx --configuration Release
```

## ソースコードから実行

```powershell
dotnet run --project src/TrackMatch.App
```
